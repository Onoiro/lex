# Ежедневный отчёт и метрики — расшифровка

Справка по формату ежедневного отчёта, который приходит в Telegram в 00:05 UTC
за прошедший UTC-день (задача B-12, `proxy/services/report.py`).

---

## Заголовок

```
📊 Lex daily report — 2026-09-21 (UTC)
```

Дата — за какой UTC-день отчёт (не за «вчера по местному времени»).

---

## 💰 Spend (траты)

```
💰 Spend: 15420 chars (1200 translate / 3420 TTS) ↑
```

- **Общая цифра** — сколько символов реально ушло в Yandex API за день
  (translate + TTS вместе). Это деньги: Yandex тарифицирует по символам.
- **В скобках** — разбивка: перевод / озвучка отдельно.
- **Стрелка ↑ / ↓** — сравнение с позавчерашним днём:
  - `↑` — потратили больше, чем позавчера;
  - `↓` — потратили меньше;
  - без стрелки — одинаково или нет данных за позавчера.

Смотрите на этот показатель, чтобы заметить аномальный рост расходов.

---

## 👥 Uniques

```
👥 Uniques: 23 devices / 15 IPs
```

Сколько **разных** устройств и IP-адресов обращалось к API за день.

- **devices** — уникальные `X-Device-Id` (реальные пользователи;
  клиент шлёт UUID из localStorage).
- **IPs** — уникальные IP-адреса (включая запросы без device ID).

Devices > IPs — несколько устройств за одним NAT (семья/офис), это норма.
Devices растёт, а IP нет — все за одним NAT.

---

## 📈 Requests — запросы по эндпоинтам

Сколько раз каждый эндпоинт был вызван за день (со стрелками к позавчера).

**translate** — переводы слов (`POST /translate`).
Основная «платная» нагрузка. Растёт — люди активно переводят.

**tts** — озвучка слов (`POST /tts`).
Вторая «платная» нагрузка (SpeechKit). Часть запросов отбивается кэшем —
см. Cache hit rate ниже.

**dictionary** — запросы к словарю (`POST /dictionary`, Yandex Dictionary API).
Пользователь открывает словарную статью с примерами употребления слова.
**Бесплатный эндпоинт**: не расходует ни квоты пользователей, ни глобальный
бюджет. Растёт — люди пользуются словарём.

**languages** — загрузка списка поддерживаемых языков (`GET /languages`).
Служебный: клиент делает его при первом открытии переводчика / смене языков.
Много запросов = много новых сессий (или много перезапусков приложения).

**quota** — запросы остатка квоты (`GET /quota`).
Это НЕ действия пользователей, а служебный трафик приложения: клиент сам
спрашивает «сколько у меня осталось», когда:
- открывается страница Перевода (индикатор «Перевод: X/500 · Озвучка: Y/500»
  под языковой панелью);
- открываются Настройки → раздел «Лимиты использования».

Большое число — норма, растёт вместе с числом открытий приложения.
Косвенный показатель активности (сколько раз открывали переводчик/настройки).

**feedback** — отправка сообщений обратной связи (`POST /feedback`).
Каждый успешный показ = одно письмо пользователя.

## 💾 Cache hit rate

```
💾 Cache hit rate: translate 62%, TTS 71%
```

Какой процент запросов **обслужен из кэша**, без обращения к Yandex API:

- `translate 62%` — из 412 запросов на перевод 62% нашли готовый перевод
  в SQLite-кэше (7-дневный TTL). Это сэкономленные символы = сэкономленные
  деньги.
- `TTS 71%` — то же для озвучки (кэш до 5000 записей). Плюс на клиенте есть
  свой Cache API для аудио, поэтому серверный hit rate может быть ниже
  реальной экономии.
- `—` (прочерк) — за день не было ни одного запроса к этому сервису,
  процент не считается.

Чем выше, тем лучше: каждый hit — это вызов Yandex, за который не платим.

## ❗ Errors — коды ошибок применительно к Lex

Все коды считаются за UTC-день. Каждый код означает конкретную ситуацию:

**400 — Bad Request (плохой запрос)**
Клиент прислал что-то некорректное: пустое слово/текст, текст длиннее
500 символов, неверная категория feedback, сообщение короче 10 символов.
Немного — норма (случайные клики, мусорные запросы). Растущий поток —
возможно, кто-то сканирует API на прочность.

**403 — unauthorized (нет/неверный токен)**
Запрос без заголовка `X-App-Token` или с неверным токеном. Проверяется
в middleware раньше всего остального. Это чужие боты и скрипты, дёргающие
API без секретного токена, вшитого в APK. Единичные — фоновый шум;
сотни за час — целевой скан (на этот случай есть отдельный алерт).

**426 — update required (устаревшая версия клиента)**
Клиент прислал `X-App-Version` старше, чем `MIN_APP_VERSION` на сервере.
Появляется только когда version gate включён на сервере. Рост означает:
у пользователей накопились старые версии, которые не обновились
(и они увидят полноэкранную заглушку «обновите приложение»).

**429 — превышение лимитов (rate limit / квоты)**
Два случая:
- слишком много запросов в минуту (лимит 30/мин на эндпоинт на IP);
- исчерпана дневная квота: личная 500 симв/день (device), IP-лимит 3000
  (антибот-слой) или anon 100 (клиент без device ID).

**Это НЕ авария** — лимиты работают как задумано. Высокое число = квоты
реально кого-то ограничивают (можно оценить, не занижены ли лимиты).
Алерт приходит только при аномальном всплеске (100+ за час).

**502 — ошибка Yandex API (upstream failed)**
Прокси получил запрос пользователя, но не смог получить ответ от Yandex
(сеть, недоступность API, проблема с ключом). Самый важный код для
работоспособности: пользователь страдает прямо сейчас. 5+ за час
приходит алерт. Единичные — сетевые глитчи, постоянные — повод проверить
ключ/аккаунт Yandex Cloud.

**503 — глобальный дневной бюджет исчерпан** (`service_overloaded`).
Финансовый предохранитель: когда суммарные траты всех пользователей
достигают `GLOBAL_DAILY_CHAR_LIMIT`, прокси отказывает ВСЕМ новым
переводам/озвучке до полуночи UTC. В норме = 0. Если есть — весь день
сервис фактически не работал для новых переводов (кэш продолжал работать).

## 💬 Feedback received

Сколько feedback-сообщений доставлено в Telegram за день (успешных отправок).

## Алерты (мгновенные сообщения) — шпаргалка

Отдельно от отчёта приходят немедленные алерты:

- `⚠️ Global budget N% used (X/300000 chars)` — бюджет пересёк порог
  (по умолчанию 80%, алерт раз на каждые 10% в день: 80%, 90%).
- `🛑 Global daily budget exhausted (...)` — бюджет исчерпан, все запросы
  получают 503 до полуночи UTC (раз в день).
- `🚨 Spike: 5× HTTP 502 in the 2026-09-22T18 UTC hour bucket` — всплеск
  ошибок за UTC-час. Пороги: 502 ≥ 5, 403 ≥ 100, 426 ≥ 50, 429 ≥ 100
  (раз на часовой бакет).
- `⚠️ SQLite недоступна: кэш/квоты деградировали до in-memory` — база
  недоступна, кэши и квоты работают в памяти и не переживут рестарт
  (раз в день).

Пороги настраиваются через env: `ALERT_BUDGET_WARN_PERCENT`,
`ALERT_HOURLY_502`, `ALERT_HOURLY_403`, `ALERT_HOURLY_426`,
`ALERT_HOURLY_429` (см. `.env.example`).

Личные квоты пользователей (500/день) НЕ алертятся — их исчерпание норма.

---

## Как посмотреть метрики руками

```bash
curl -H "X-App-Token: <token>" https://lex.2-way.ru/metrics
```

Возвращает счётчики за текущий UTC-день (JSON): те же counters + uniques.
Полезно для оперативной проверки в течение дня, не дожидаясь отчёта.
