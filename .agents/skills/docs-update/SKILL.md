# Docs Update — синхронизация документации с кодовой базой

## Когда срабатывать

### Автоматически (в конце задачи)

После завершения задачи разработки — проверить, затронуты ли триггеры (см. раздел «Триггеры»). Если хотя бы один триггер сработал — выполнить синхронизацию. Если ни один — ничего не делать, сообщить одной строкой: «Документация актуальна, правки не требуются.»

### Вручную

По фразам пользователя: «обнови документацию», «синхронизируй доки», «готовим к пушу», «проверь доки», «обнови README», «обнови KODA.md» и подобным.

## Триггеры

Навык запускается, если в рамках задачи изменилось что-либо из списка ниже. Изменения только внутренней реализации (рефакторинг без изменения API/структуры) **не** являются триггером.

1. **Структура каталогов** в `client/src/` или `proxy/` — добавлены, удалены, переименованы папки или значимые модули (новые файлы в существующих папках — не триггер, если не меняется список в документации).
2. **Makefile** — добавлены, удалены или переименованы цели (`.PHONY`-список и сами target-ы).
3. **Зависимости** — `client/package.json` (dependencies/devDependencies) или `proxy/requirements.txt`.
4. **Версия проекта** — `version` в `client/package.json`.
5. **Эндпоинты proxy** — `proxy/main.py` (добавлены/удалены/изменены маршруты).
6. **Параметры алгоритма SRS** — `client/src/domain/srs.ts`: интервалы, потолок интервала, формула веса, пороги таймера, правила паузы.
7. **Количество тестов** клиента или proxy — если число тестов изменилось и указано в README.
8. **Платформы и способы распространения** — PWA, Android, Desktop, сторы.
9. **Пользовательские сценарии** — страницы в `client/src/pages/` (добавлены/удалены/переименованы), импорт/экспорт, настройки.

## Читаемые файлы

| Файл | Зачем |
|---|---|
| `README.md` | Публичная документация (английский) — проверка и правка |
| `KODA.md` | Контекст проекта для агента (русский) — проверка и правка |
| `client/package.json` | Версия, зависимости, список страниц/скриптов |
| `proxy/requirements.txt` | Зависимости proxy |
| `proxy/main.py` | Эндпоинты proxy |
| `client/src/domain/srs.ts` | Параметры алгоритма SRS |
| `Makefile` | Список целей и их описания |
| `client/src/pages/` | Список страниц (через `list_directory`) |
| `client/src/` (структура) | Каталоги и модули (через `list_directory`) |
| `proxy/` (структура) | Каталоги и модули (через `list_directory`) |

## Изменяемые файлы

| Файл | Язык | Что обновлять |
|---|---|---|
| `README.md` | Простой английский | Структура, стек, команды, эндпоинты, алгоритм, сценарии, количество тестов |
| `KODA.md` | Русский | Структура, технологии, правила, алгоритм, версия, дата обновления, дальнейшие планы |

## Порядок работы

### Шаг 1: Сбор diff

Выполни параллельно:
- `git diff HEAD` — все изменения (staged + unstaged) с последнего коммита.
- `git diff --staged` — если есть staged-изменения.

Если diff пуст — проверь, нет ли untracked-файлов через `git status --short`.

### Шаг 2: Сопоставление с триггерами

Проанализируй diff и определи, какие триггеры из списка выше сработали. Если ни один — остановись, сообщи: «Документация актуальна, правки не требуются.»

### Шаг 3: Сбор актуальных данных

Для каждого сработавшего триггера прочитай соответствующий файл и сверь с документацией:

- **Структура каталогов:** `list_directory` для `client/src/` и `proxy/`. Сравни с деревом в README и KODA.md.
- **Makefile:** прочитай `Makefile`, сравни список целей с таблицей команд в README.
- **Зависимости:** прочитай `client/package.json` и `proxy/requirements.txt`.
- **Версия:** прочитай `version` из `client/package.json`.
- **Эндпоинты:** прочитай `proxy/main.py`, найди все `@app.get`/`@app.post`/`@app.put`/`@app.delete`.
- **SRS:** прочитай `client/src/domain/srs.ts`, проверь интервалы, потолок, формулу веса, пороги таймера, правила паузы.
- **Тесты:** запусти `make client-test` и `make proxy-test` (или прочитай вывод из покрытия), посчитай количество тестов. Сравни с числом в README.
- **Страницы:** `list_directory` для `client/src/pages/`.
- **Платформы:** проверь `capacitor.config.ts`, `src-tauri/tauri.conf.json`, `vite.config.ts` (PWA).

### Шаг 4: Внесение правок

Для каждого расхождения внеси **минимальную** правку через `replace`:

- Сохраняй существующий стиль, структуру заголовков, ASCII-диаграмму архитектуры и формат таблиц.
- Не переписывай разделы целиком — меняй только устаревшие строки.
- Не добавляй новые разделы без явной необходимости.
- Не выдумывай функциональность — только то, что подтверждено кодом.

### Шаг 5: Обновление метаданных в KODA.md

Обнови два поля в `KODA.md`:

1. **«Текущая версия»** — значение `version` из `client/package.json`.
2. **«Последнее обновление»** — текущая дата в формате `DD месяца YYYY` (например, `26 июля 2026`).

Эти поля обновляются **всегда** при срабатывании навыка, даже если остальные правки не потребовались.

### Шаг 6: Проверка количества тестов в README

В таблице команд README строка `make client-test` содержит количество тестов в описании, например: `Run client tests (vitest, 113 tests)`. Если фактическое количество отличается — обнови число. Для proxy-тестов количество в README не указывается (только команда), поэтому проверять не нужно.

### Шаг 7: Раздел «Дальнейшие планы» в KODA.md

Проверь каждый пункт из раздела «Дальнейшие планы». Если пункт фактически реализован (подтверждено кодом) — удали его из списка. Не добавляй новые пункты.

### Шаг 8: Отчёт

Выведи краткий отчёт в формате:

```
Документация обновлена:
- README.md: <что изменено и почему>
- KODA.md: <что изменено и почему>
```

Если правки не потребовались (но метаданные обновились):

```
Документация актуальна. Обновлены метаданные в KODA.md (версия, дата).
```

Если вообще ничего не менялось:

```
Документация актуальна, правки не требуются.
```

## Ограничения

- **Не переписывать документы целиком** — только точечные правки устаревших строк.
- **Не добавлять новые разделы** без явной необходимости — документация должна оставаться компактной.
- **Не менять раздел License** в README.
- **Не менять бейджи** в начале README (строки `![...](...)`).
- **Не выдумывать функциональность** — только то, что подтверждено кодом.
- **Не делать `git push`** — это делает пользователь.
- **README — только простой английский**, понятный non-native speakers.
- **KODA.md — только русский.**
- **Не менять ASCII-диаграмму архитектуры**, если только архитектура кардинально не изменилась.
- **Не трогать комментарии в коде** — навык работает только с README.md и KODA.md.

## Пограничные случаи

- **Diff пуст, но пользователь вызвал вручную:** выполни полную проверку всех триггеров. Возможно, документация рассинхронизирована ранее.
- **Несколько триггеров сработали одновременно:** обрабатывай каждый независимо, но правки вноси за один проход по каждому файлу.
- **Новый файл в существующей папке (например, новый компонент):** это не триггер, если список в документации не перечисляет отдельные файлы. Но если в KODA.md перечислены файлы папки (например, `domain/ — srs.ts, stats.ts, validators.ts`) — обнови список.
- **Удалён файл:** если файл упоминался в документации — удали упоминание.
- **Переименование:** обнови все упоминания старого имени на новое.
- **Тесты не запускаются (окружение):** если не удаётся запустить тесты, пропусти шаг 6 и сообщи об этом в отчёте.
